## 方向(为什么是这些)

产品核心场景 = 电脑浏览/管理手机文件 + 双向高速传输(交接文档 §1/§4)。当前缺口按用户可感知度排序:

1. **上传方向不存在**——只能下载,不能把文件推进手机(装 APK/推媒体是高频需求)
2. **主场景未验证**——手机当服务端、PC 当客户端浏览手机存储,从未 E2E(此前都是反方向)
3. **R-013 协议路径语义**(对抗测试发现)——虚拟路径 `/name` 在 Windows 服务端 403,第三方客户端不可用;FsEntry.path 泄露主机盘符布局(§7)
4. **相册快路径**——浏览手机相册是最高频场景,逐目录 walk 慢且乱

## 工作流(依赖序)

| # | 工作流 | 内容 | 验收 |
|---|--------|------|------|
| WS1 | 协议虚拟路径(R-013) | PathGuard:前导 `/` = 共享根内虚拟路径(主机绝对路径仅当已在根内时接受,向后兼容);LocalVfs list/stat 返回虚拟路径(`/`=根),主机布局不再出协议 | server/core 单测扩展(虚拟路径往返、穿越仍 403、盘符路径不再泄露) |
| WS2 | 上传通道 | MlfClient.upload:远端 `<name>.mlfpart` 断点上传(offset=远端已有长度)→ 完成后 fs/op rename 原子落名;浏览页「上传到当前目录」(file_picker 多选,PC/手机通用);TransferTask 支持 upload 方向 | 单测(断点续传/改名)+ 真机 PC→手机上传 |
| WS3 | 反向主场景 E2E | 手机端 `mlf-server.flag` 文件触发自动开服务(配对 JSON 进 logcat);桌面端 `MLF_PAIR_FILE` 自动连接;跑通 PC 客户端 → 手机服务端:浏览 / 下载 / 上传 | 多 agent 独立回归(见 WS6) |
| WS4 | 相册快路径 | server 包 `GET /api/v1/media/list?bucket=&type=&since=&limit=`:已知桶(DCIM/Pictures/Screenshots/Movies/Music/Download,深度≤3 walk)+ 扩展名分类 + mtime 倒序分页。**本轮做目录桶版(纯 Dart 跨平台)**;原生 MediaStore 通道待真机性能数据再决定(登记 risks) | 端点单测(桶发现/类型过滤/分页/穿越免疫) |
| WS5 | 健壮化 | R-014 实现:/pair 从黑名单豁免(pair 自身失败仍计数限速);队列自动重试(指数退避 2s/8s,至多 2 次,取消优先);`.part` 策略文档化(保留=续传价值) | 单测(豁免语义/退避) |
| WS6 | 多 agent 独立回归 | 按决策人既定方法论:①协议对抗 agent(含新路径语义+上传穿越)②真机双向矩阵 agent ③完整性校验 agent | 全 PASS + 新发现入 risks |
